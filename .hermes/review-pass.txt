REVIEW: S1.12 Phase 2 — Cross-domain tracking
==============================================

## 1. AGENT-REVIEW — bugs, edge cases, invariants

### Changed: src/Hive/Hive.php:614-624 (+12 lines)
Adds cross-domain check in `recordDiscovery()`: when `mode==='compose'`, queries
`laws` table for same formula in DIFFERENT domains. If found, logs CROSS_DOMAIN.

### Edge cases analysed:

**(a) mode null safety**: `($d['mode'] ?? '') === 'compose'` — null coalescing
handles missing key. ✓

**(b) Duplicate CROSS_DOMAIN logs**: `recordDiscovery` deduplicates by
`$this->knownLaws`, so each (atom, domain) pair fires at most once. When atom
appears in domains A→B→C, you get 2 logs (B-found-A, C-found-A+B) — correct;
each log captures the growing domain set. ✓

**(c) SQL injection**: Uses PDO prepared statement with positional `?` params. ✓

**(d) PDO portability**: Uses `?` placeholders — PDO rewrites per driver. Works
on both SQLite and PostgreSQL. ✓

**(e) fetchAll(FETCH_COLUMN)**: Returns flat array of domain strings — correct
input for `implode()`. ✓

**(f) Domain ordering**: `array_merge([$domain], $crossDomains)` puts current
domain first. `$crossDomains` has no ORDER BY (non-deterministic but acceptable
for logging). ✓

**(g) Performance**: One SELECT DISTINCT per new compose atom. `laws` table row
count is moderate at Stage 0. An index on `(formula, domain)` would help at
scale — acceptable for prototype. ✓

### Invariants preserved:
- No side effects on grammar, task state, or DB beyond logging
- `recordDiscovery` return type unchanged (void)
- `$foundAny` propagated correctly — new code doesn't touch it
- Read-only query — no data corruption risk
- Grammar already auto-grows via existing `$g->add()` + INSERT OR IGNORE

## 2. PROTOCOL CHECK

| Check | Status | Detail |
|-------|--------|--------|
| Only compose atoms tracked | PASS | `mode === 'compose'` guard — raw/heldout atoms not checked |
| Cross-domain query correct | PASS | `domain!=?` excludes current domain, `DISTINCT` deduplicates |
| Log format readable | PASS | `"CROSS_DOMAIN: atom now in [domainA,domainB,...]"` |
| No INSERT before check | PASS | Cross-domain query runs BEFORE INSERT OR IGNORE — so it finds atoms from prior ticks, not the one being inserted now |
| Grammar growth untouched | PASS | Existing auto-discover + INSERT path unchanged |

Note: the INSERT OR IGNORE for the *current* atom happens AFTER the check. So
the cross-domain query only finds atoms from PRIOR ticks/domains — correct. The
current atom's own domain won't appear in `$crossDomains` until the next
cross-domain check for another domain.

## 3. STRATEGIC GATE

Cross-domain tracking is essential infrastructure. When an atom proves useful
across ≥2 domains, it signals generality — the core property we're hunting
(CV→0). This log gives the daemon a signal it can eventually act on (e.g.,
promoting cross-domain atoms to a shared grammar pool, weighting them higher in
bees, or triggering deeper analysis).

Minimal implementation — 12 lines, no refactoring, no new abstractions. The log
is currently informational; future phases can build on it.

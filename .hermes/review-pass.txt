=== 3. STRATEGIC GATE ===

Is the design sound? YES.

Pattern: Header extraction at scan time → JSON-encoded storage in SQLite accumulator → decoded array in task structure → forwarded to Search::find as label map.

Key design decisions:
- Labels extracted from file content (CSV/markdown), not from external metadata — self-contained, no side channel needed.
- JSON encoding for transport through SQLite (fd table is in-memory, laws table is persistent) — consistent serialization format.
- featName closure with ?? fallback — single point of naming logic, no scattered x\d+ regex.
- rawFeatNames set replaces regex — the old regex `preg_match('/^x\d+$/', $fname)` would fail when labels contain digits (e.g., "x1" as a label name would be incorrectly treated as a raw feature). The set-based approach correctly identifies raw features regardless of naming scheme.

No architectural debt: no hardcoded paths, no duplicate logic, no bypass of core pipeline. The labels flow naturally through the existing task structure.

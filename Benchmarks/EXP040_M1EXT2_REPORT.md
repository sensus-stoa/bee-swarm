## Проблема

EXP-040 SUM-дефицит: dot/kinetic 0/20 на depth-2. Дебаг (§0b хендоффа): срез
пула по порядку генерации + beam по quick-cv одиночки убивают композиционные
цветки до сборки (произведение плохое само, сумма точная).

## Диагноз (трассировка, точные данные)

Три точки смерти, найдены трейсом T0/T1/T2 (trace_sum4.py, trace_rank.py):

1. **Перезапись пула**: WU-2 rawPairKeys вычислялись, но beam>0 ветка
   перезаписывала $pool дескрипторами — rawPairKeys выбрасывались.
2. **Все дескрипторы cv-ранжированы**: (x1×x4) — cv-ранг 766/1318 (cv=5.06),
   топ-30 scored = 19 R/K-форм. Родители суммы не доходят до pair-loop.
3. **Полный закон не выразим за 1 вылет**: брут-форс ВСЕХ L1×L1 (реальные
   вектора, sim_quota.py) — лучший cv≈1.73 (шум). Закрытие = лестница
   через trail marks (2+ вылета).

## Механизм (3 WU, все по данным проб)

- **WU-1b corr-квота с класс-слотами** (`SEARCH_BEAM_SIGNAL_K=15`,
  `SEARCH_BEAM_SIGNAL_PAIR_K=8`): top-M по |corr| в beam-пул, R/K исключены;
  слоты разделены 8 raw-pair + 7 прочих (единая квота вытесняется sq-композитами
  — trace_sigtail: (x1×x4) выпадал из top-15 полного пула).
- **WU-4b trail marks**: запись топ-5 сигнальных форм при !found, сортировка
  по CORR (cv-сортировка тащит шум: sim_flight A 3/3 vs B 0/3); класс-фильтр
  «продукт двух raw-пар» (без него corr 0.84 у ((x1²−x2)×(x3²+x5)) выше
  law-суммы 0.82 — diag_beam10_read); промоция uses≥2 → 'replicated';
  sweep ТОЛЬКО uncalibrated uses>7 (старый DELETE uses>6 стирает
  подтверждённую метку при рое 20 пчёл); потолок replicated топ-32/fingerprint.
  DDL: колонка corr (PRAGMA-проверка, fail-loud ALTER без try/catch).
- **WU-4c read-путь**: следующий вылет читает топ-10 меток по
  (uses DESC, corr DESC), re-evaluate формулы на СВОИХ X (signal must
  replicate — передача чужих векторов = подглядывание), инжект в pair-пул.
  Ядро лестницы: метка⊕родитель = полный закон.

## Честный гейт: kinetic НЕ ЗАКРЫТ (FAIL-unstable)

Хронология: (1) симуляции предсказывали недостижимость на depth-2 — ВЕРНО для
d=2, НО verify-полёты ЭСКАЛИРУЮТ (SEARCH_DEPTH_MAX не задан в verify → default 4,
ADAPTIVE-DEPTH 09.08) → kinetic-закон m(v1²+v2²+v3²) выразим на d=3-4 (L2L1:
(v1²)×m, сумма трёх L2L1). (2) ОДИН прогон дал 19/20 PASS cvH=0.0000 (формула
((x0×x1²)+((x0×x2²)+(x0×x3²)))) — НЕ воспроизведён: повторные прогоны 0/20
(plain quota и class-quota L2-freeze — оба 0/20).

Вердикт: критерий ≥10/20 НЕ выполнен воспроизводимо. Наблюдение 19/19→0/20 —
нестабильность состояния (подозрение: накопленные законы/борн-атомы в файловой БД
меняют путь эскалации между прогонами; точный механизм — следующая сессия с
phpspy-attach на расхождении). НЕ подгоняем критерий (канон §7).

Дорожная карта kinetic: (a) зафиксировать SEARCH_DEPTH_MAX=4 в verify-протоколе
явно, (b) phpspy-сравнение расходящихся прогонов, (c) метки depth-классов.

Механизм v3 (эволюция v2):
1. **Residual ladder**: лестница = координаты; глубина фикс, растёт число координат
   (директива owner: глубина — самоувеличивающийся параметр роя).
2. **Orbit completion**: структурное завершение орбиты (ступень → недостающие соседи,
   T1 (x0×x1²) без порогов). Источник: аналитик §2.4.
3. **Joint fold-gain Δ_h(f|B) = 1 − RSS_h(B+f)/RSS_h(B)**: единственный ранг, при
   котором точный член (T1, маргинальный corr 0.22) выигрывает у монстра-смеси
   (in-sample var ≡ corr по порядку — фатально для single-fit отбора).
4. **Writer v3**: покрытие классов без порогов (3 лестницы + лепестки по группам
   second-operand), классы от генератора ($l1PairwiseMap) — ноль регексов.

Инструментальный урок: phpspy leaf-гистограммы на живых воркерах дали все корни за

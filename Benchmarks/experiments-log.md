## ЭКСП-001 (05.08.2026) — Бейзлайн: random search vs systematic

**Гипотеза:** random search с тем же бюджетом найдёт ≥95% законов систематического поиска → эволюция не нужна.

**Метод:** scripts/baseline_random.php, бюджет 2000 eval, BASE_OPS грамматика
(+ × − / min max sq), данные: синтетика (ADD/MUL/XOR/NOISE) + реальные.

**Результат:**

| Данные | Random | Systematic | CV |
|--------|--------|------------|-----|
| ADD (y=x0+x1) | ~140 | (x0+x1) | 0 |
| MUL (y=x0×x1) | ~150 | (x0×x1) | 0 |
| XOR (y=(x0−x1)²) | 0 | ((x0−x1))² | 0 |
| NOISE | 0 | none | — |
| metrics (7→intact) | 489 ложных (24%) | (disc/R+disc)max(gi/R+gi) | 0.082 |
| wine (12→alcohol) | 214 | Rrangex0+Rnormx11 | 0.048 |
| auto-mpg (→mpg) | 0 | none (после фикса NaN) | — |

**Выводы:**
1. Random НЕ находит композитные формулы (XOR = L1→L2) — дифференциал композиции
2. Random на реальных коррелирующих данных даёт 24% ложных хитов — нужна null-калибровка
3. Systematic находит осмысленные законы: intact = max(норм.дисциплина, норм.GI) CV=0.082

**Найденные баги (побочный эффект бейзлайна):**
- БАГ-A: NaN/INF проходили exact-match как «закон» CV=0 (abs(NaN−y)>0.0001=false).
  Причина: array_product 392 значений = INF → INF×0 = NaN. Фикс: is_finite guard
  в Search::cv и exact-check. Тест: NanGuardTest.
- БАГ-B: NullCalibrator fallback 0.01 — не калибровка, а дефолт. На shuffle
  Search::find(depth=1) даёт 9.99 → nActual<2 → fallback 0.01 → система слепа
  к слабым законам (wine CV=0.048 не прошёл бы). Фикс: fallback 0.15.
- БАГ-C: рассинхрон порогов: Search::find хардкодит 0.15, DiscoveryEngine
  использует getEpsilon ?? 0.01. Фикс: единый 0.15.

**Физика auto-mpg (подтверждение интуиции):**
mpg ≈ 100227 × weight^−1.06 (CV=0.163, степенной закон, b≈−1)
«Чем тяжелее машина, тем меньше миль на галлон» — закон есть, но CV чуть выше
порога 0.15 из-за шума данных (год, происхождение, цилиндры). PySR дал бы тот же CV.

## ЭПИСТЕМОЛОГИЧЕСКАЯ ПОЗИЦИЯ (05.08.2026, ответ hostile reviewer №1)

**Система находит КОРРЕЛЯЦИИ, а не ЗАКОНЫ.**
- CV→0 = устойчивость корреляции на наблюдаемых точках
- held-out = фальсификация (отбрасывание), не верификация (Поппер)
- «Закон» = человеческая интерпретация устойчивой корреляции в домене
- extrapolation=UNKNOWN — честная граница, не скрываемая
- Корреляция может быть локальной: «закон» в узком домене, мусор вне его
- Единственный путь корреляция→закон: интервенция (Стадия 3, каузация)

**Запись в протокол:** каждое открытие — «корреляция CV=x на N точек,
домен=D, не опровергнута на held-out. Законом НЕ объявляется.»

**Метод:** 50 валидных судоку (перестановки цифр базового решения, сумма каждой

**Результат:**
- Forager: 28 задач (пары клеток, 50-73 строки) — CSV разобран корректно
- Foraged-открытий: **0** (27 открытий — только синтетика compose)
- Пары клеток судоку НЕЗАВИСИМЫ → CV высокий → рой честно молчит

**Выводы:**
1. Рой НЕ галлюцинирует связи на независимых данных (контраст: random search
   на коррелирующих метриках даёт 24% ложных хитов без null-калибровки)
2. ГРАНИЦА ВЫРАЗИМОСТИ: инвариант «сумма строки = 45» требует оператора

   позволил бы открыть инвариант судоку за секунды.

**Демонстрационная ценность:** «рой не выдумывает законы там, где их нет» +

### Дополнение 2 (шумовой sweep, после SEARCH-TOP-K ab737df)
y = 2x + N(0,σ), n=20, held-out живой:
| σ | gplearn | Bee Swarm |
|---|---------|-----------|
| 0.01-0.25 | находит | находит (ПАРИТЕТ, cv_test 0.0008-0.020) |
| 0.50 | находит (0.035) | ОТКАЗ |
| 1.00 | находит (0.069) | ОТКАЗ |

огромен. gplearn (MSE) не видит: абсолютная ошибка 0.5 везде одинакова.

- MSE = абсолютная точность (предсказание близко по величине)
- CV = относительная (отношение сохраняется — правильно для законов

Плата: при вырожденных малых x наш отказ избыточно строг. Для честного
сравнения: x ≥ 1 (без экстремально малых) или tMin с учётом шума.

## ЭКСП-010 (05.08.2026) — Domain of validity of CV criterion

Гипотеза: CV имеет преимущество при мультипликативном/масштабном шуме,
избыточно строг при аддитивном около нуля. Данные: один источник (seed 42,
/tmp/cvmatrix/*.csv), оба метода, n=20, тест 20%.

| Данные | gplearn (MSE) | Bee Swarm (CV) | Итог |
|--------|---------------|----------------|------|
| мульт. 0.1x·noise, x∈[0.1,5] | 0.0429 PASS | 0.0344 PASS | паритет |
| аддитив 2x+0.5 | 0.0000 PASS | 0.0010 PASS | паритет* |
| гаусс σ=0.1 | 0.0133 PASS | 0.0133 PASS | паритет |
| мульт., x∈[1,10] | 0.0767 PASS | 0.0648 PASS | паритет |
| мульт., x∈[0.1,1] | 0.0132 PASS | 0.0072 PASS | паритет |

*аддитив: наш поиск нашёл 3x+1 — почти пропорциональна 2x+0.5 на узком
диапазоне (ratio 1.528→1.524, CV≈0.001). CV ищет СОХРАНЕНИЕ ОТНОШЕНИЯ,
не точную форму — философия, не баг.

ВЫВОД: паритет на умеренных шумах. Расхождение (отказ CV) — только при
ЭКСТРЕМАЛЬНОМ относительном шуме: абсолютный шум σ=0.5 при малых x
(y≈0.2, шум 250%) → cv_train(2x)=0.31 > порога → 2x вне plausible →
честный отказ. MSE принимает (абсолютная ошибка 0.5 «мала»).

ГРАНИЦА ПРИМЕНИМОСТИ CV (формулировка для публикации):
CV = критерий сохранения ОТНОСИТЕЛЬНЫХ инвариантов. Подходит для классов
законов, где масштабирование часть структуры (F=ma, PV=nRT: ошибка 10 Па
при 100 Па ≠ при 1000 Па). В областях, где абсолютная ошибка — правильная
модель (температура около нуля, фиксированный предел прибора), CV может
сознательно отказывать там, где MSE принимает. Это не дефект, а выбор
эпистемики: «наблюдаемые данные недостаточно поддерживают инвариант».

Раздел для статьи: "Failure modes and boundaries of epistemic validation".

## ЭКСП-012 (05.08.2026) — Знакопеременные цели: подтверждённый пробел CV

Рецензия на протокол: «CV плохо определён, когда целевая переменная проходит
через ноль или меняет знак; калибровочный набор — всегда-положительные».

ПОДТВЕРЖДЕНО экспериментом:
- y = x−5 (x∈[1,10], переход через 0): НЕ НАЙДЕН
- y = 2x−10: НЕ НАЙДЕН
- y = sin(x): НЕ НАЙДЕН

ДВЕ причины:
1. CV = std(pred/y)/mean(pred/y): при y=0 деление на 0 → INF; знакопеременный
   ratio → CV→∞. Метрика определена только для ПРОПОРЦИОНАЛЬНЫХ законов (y=ax).
2. Константы грамматики {K1=1, K2=2}: аффинный сдвиг −5 требует глубины 5
   (x−1−1−1−1−1) — вне depth 2-3.

СЛЕДСТВИЕ: аффинные законы (v=v₀+at, x=x₀+vt) НЕ ОТКРЫВАЕМЫ. Здесь gplearn
(MSE) нас бьёт: y=x−5 он найдёт. Граница CV шире, чем думали: не только
«экстремальный относительный шум», но и «любой сдвиг».

ФИКС-СТОРИ: AFFINE-LAWS (сдвиг-инвариантная мера + константы).
Связь: ЭКСП-010 (граница CV) уточняется: CV покрывает y=ax-класс, не y=ax+b.


### Дополнение ЭКСП-012 (фаза 1 AFFINE-LAWS)
Сдвиг-метрика работает: y=x−2 (выразимый, K2=2) найдена как (x0−K2),
CV_test<0.10; y=2x−2; testRatio=0.5 с нулём в train — ок.
НАХОДКА: y=x−5 (константа 5 вне {1,2}) — система находит «пропорциональную
тень»: ((x−(x/Rx))×(x+Rx)²) даёт pred=138874 при y=12, НО CV=0.002 —
отношение pred/y почти константно на хвосте (y≈x). CV не различает
x−5 и 8680x при невыразимом сдвиге. ГРАНИЦА ВЫРАЗИМОСТИ (константы),
не метрики. Фаза 2 AFFINE-LAWS: эволюционируемые константы.

### Дополнение (05.08 вечер): R-формы vs законы — неразличимы на срезе
С POST-фиксами (R-статистики по train, cv_train победителя): R-форма
((x0+K2)−(x0×R+x0)) = 2−31x проходит held-out (cv_test=0.008) на y=2x+шум.
Причина: CV определяет КЛАСС ПРОПОРЦИОНАЛЬНОСТИ (y∝x), константа масштаба
произвольна (масштабная инвариантность). Различие R-формы от закона —
только на НОВЫХ данных (перенос): 2x даёт y/x=2, R-форма с train-масштабом
— нет. Вывод: срез held-out не различает масштабные эквиваленты;
внешний контур (HOLDOUT-TEST-AGENT) обязателен для отсева R-форм.

## ЭКСП-022u (ЗАПЛАНИРОВАН, рецензент-финал 14.08) — тест трансляции ВНУТРИ класса

Рецензент: «сравнение инвариантов vs случайных строк — почти тавтология.
Нетривиальное: среди атомов-ИНВАРИАНТОВ высокий-reuse предсказывает
transfer-успех лучше низкого-reuse (при контроле на инвариантность!)».

ДИЗАЙН: A→B прогоны; все атомы — РЕАЛЬНЫЕ инварианты (найдены на A!);
группа HIGH = атомы с reuse≥k в A, группа LOW = reuse≤m; контроль —
инварианты на ПЕРЕСТАВЛЕННЫХ данных (шум-инварианты!). Метрика:
transfer-успех в B. Таблица 2×2: (прижился/нет × HIGH/LOW).
Гипотеза: HIGH > LOW. До этого: 022t доказывает ТОЛЬКО
«опытные атомы ≠ шум» (Fisher 1e-5), НЕ трансляцию.

### ЭКСП-022u: КОНТРОЛЬ CONFOUNDER (рецензент-финал, ОБЯЗАТЕЛЬНО до запуска!)

Связь reuse→transfer может идти ЦЕЛИКОМ через complexity:
parsimony (λ=5e-5) → простые атомы живут дольше + переиспользуются чаще
+ лучше переносятся (меньше переобучены!). Тогда reuse не несёт
дополнительной информации.

ОБЯЗАТЕЛЬНЫЙ ДИЗАЙН (вариант А, чище):
- HIGH-reuse vs LOW-reuse ТОЛЬКО внутри ОДНОЙ КОРЗИНЫ сложности
  (strlen/depth/число узлов в узком диапазоне!);
- контроль на переставленных данных — ТОЙ ЖЕ сложности (иначе
  контроль нечестен!);
- плюс вариант Б (регрессия): transfer_success ~ reuse + complexity +
  возраст_атома; коэффициент при reuse значим ПОСЛЕ контроля complexity
  и возраста (старые атомы успели и reuse накопить, и обкататься!).

### ЭКСП-022u: ТРИ СТРАХОВКИ ИСПОЛНЕНИЯ (рецензент-финал, до прогона!)

1. ПРЕДРЕГИСТРАЦИЯ ТОЧЕК РАЗРЕЗА (до первого запуска!):
   - HIGH vs LOW: медиана? квартили? — ЗАФИКСИРОВАТЬ;
   - transfer_success: бинарный (выжил/умер в B)? непрерывный (CV)?
     число reuse в B? — ЗАФИКСИРОВАТЬ (от этого: логистическая vs
     линейная модель!).
2. КОЛЛИНЕАРНОСТЬ reuse↔возраст: проверить VIF; если высокий —
   стратификация по возрасту или осторожная интерпретация (иначе
   «значимость» прыгает от спецификации!).
3. РЕГРЕССИЯ — ОСНОВНОЙ ТЕСТ (complexity непрерывно!), корзины —
   robustness-проверка. Корзины с n<10 атомов НЕ интерпретировать
   (Fisher — артефакт малой выборки!).

Оба исхода публикуемы: (а) reuse значим после контроля → «трансляция»
возвращается без оверклайма (уровень Artificial Life/ECJ!);
(б) не значим → «отбор порождает простоту, простота переносится» —
формулировка 022t была верной верхней границей.

### ЭКСП-022u: ДВА УТОЧНЕНИЯ ИНТЕРПРЕТАЦИИ (рецензент-финал)

4. РАЗМЕР ЭФФЕКТА, НЕ ТОЛЬКО ЗНАЧИМОСТЬ: зафиксировать ВЕЛИЧИНУ
   коэффициента при reuse + порог практической значимости ДО прогона
   (коэффициент при reuse объясняет ≥X% дисперсии transfer сверх
   complexity+age). «p<0.05, но крошечный коэффициент» = «трансляция
   слабая», не «основной механизм» — заявка скромнее!
5. ПРЕДРЕГИСТРАЦИЯ САМОЙ СПЕЦИФИКАЦИИ РЕГРЕССИИ: функциональная форма,

### ПРЕДРЕГИСТРАЦИЯ EXP-030 (26.08.2026): CULTURE AS SEMANTIC COMPRESSION

### ПРЕДРЕГИСТРАЦИЯ EXP-031-v2 (26.08.2026): CONTEXTUAL CULTURAL RETRIEVAL

**Гипотеза:** Previously acquired atoms improve deep symbolic discovery only

**Архитектурная рамка (3 уровня памяти):**

2. Ассоциативная память: контекст → полезные продолжения (граф переходов) — БУДУЩЕЕ
3. Рабочая память: 3-5 активных атомов на задачу — РЕАЛИЗУЕМ СЕЙЧАС

**Формула relevance (ПОЛНАЯ — требование пользователя):**
R(z|e) = ΔCV_inner(z|e) − λ·C(z) − μ·D(z,A) + η·P(z|context)

где:
- ΔCV_inner = CV(e) − min CV(e op z), op ∈ {+,−,×,/} (помогает сейчас)
- C(z) = complexity penalty (strlen раскрытого z / 10)
- D(z,A) = redundancy с уже активированными атомами (max |ρ| к ним)
- P(z|context) = культурный prior (reuse_count атома / max reuse; 0 на старте)

**Константы (заморожены ДО прогона):**
λ = 0.01 (слабый complexity штраф)
μ = 0.05 (существенный redundancy штраф)
η = 0.1 (умеренный prior boost)
K (top extensions per step) = 2
B (top hypotheses) = 3
max retrieval cycles = 2

**Механизм (потоковый, O(n) памяти):**
for each cultural atom z:
  vec = evaluate(z)      // временный вектор
  gain = oneStepGain(e, vec)
  updateTopK(best, z, gain)
  free(vec)
Никаких 32 колонок в Search!

**Протокол:**
1. depth3 Search нетронут (база)
2. culture НЕ добавляется глобально
3. top-3 текущих hypotheses
4. для каждой — все atoms одним оператором (потоково)
5. K=2 лучших extensions
6. max 2 cycles
7. финальная формула раскрывается
8. holdout untouched (relevance по TRAIN inner-fit!)
9. только HEAT
10. Успех: ≥10/20 при bounded RAM

Если 0/20 → systematic search несовместим с compositional transfer,
нужна другая search paradigm (фиксируем как архитектурную границу).

## АКАДЕМИЧЕСКИЙ АУДИТ (29.08): позиция vs arXiv/SRBench/related work

**Прямых аналогов механизма НЕ найдено (3 поисковых запроса через MCP:**
**arxiv+openalex, web, academic):**

1. **GP-GOMEA (Virgolin, Bosman 2022, arXiv:2204.12159)** — топ SR через
   gene-pool optimal mixing + coefficient mutation. НЕТ: ресурсной экономики
   спавна, сохранения частичных гипотез как наследуемых атомов, birth-гейтов.
   Близко по духу (mixing ≈ chunk-переиспользование), но chunk — код-поддерево,
   не эволюционирующий концепт с lineage.

2. **QDSR / Quality-Diversity SR (Baidu Scholar hit)** — exact recovery 91.6%
   на Feynman-AI 117 задач через Quality-Diversity + physics constraints.
   НАМ ВАЖНО: они используют знания о физике (units/symmetry) — мы НЕТ.
   Наш heat 20/20 на 5 фичах — с нуля, без unit-table. Прямое сравнение
   некорректно (разные допущения), но QDSR — сильнейший baseline для
   Feynman-подобных задач. Цитировать обязательно.

3. **Novelty Search / MAP-Elites / QD** — это наш ближайший теоретический
   сосед (сохранение неперспективных, но разнообразных кандидатов = наш
   DormantPool). В SR-контексте НЕ применялся к «сохранению частичных
   гипотез с lineage и birth-гейтами». Это и есть новизна: DormantPool
   как hypothesis archive с эволюционной экономикой (поколения, голод,
   birthday-гейты), не как behavior-diversity archive.

4. **AI Feynman 2.0 (Udrescu & Tegmark)** — использует physics priors
   (unit table, symmetry) для РЕКУРСИВНОГО упрощения. Мы — противоположный
   полюс: без physics priors, чисто из данных + эволюции. Честная рамка:
   «AI Feynman получает физику извне; Bee Swarm выращивает её внутренне».

5. **LLM-AutoSciLab (2026, arXiv:2605.24043) + Co-Scientist** — закрытый
   цикл hypothesis→experiment→refine через LLM. Другой класс: LLM-агенты
   с внешними знаниями. Мы — эволюция БЕЗ LLM. Совпадает цель
   (closed-loop discovery), не механизм.

**ВЫВОД ДЛЯ PAPER:**
- Новизна №1: DormantPool/lineage как «hypothesis archive с эволюционной
  экономикой» — между QD-архивами и lineage-selection, в SR не применялось.
- Новизна №2: partial hypothesis → born atom → cultural inheritance
  (B-AS-ARGUMENT контракт + канонизация) — этот слой в GP-GOMEA отсутствует
  (там chunks не рождаются из слабых особей), в QDSR отсутствует (там
  архив = behavioral diversity).
- Слабое место против критиков: heat 20/20 — ОДНА задача. Нужен
  QDSR-style Feynman-AI прогон (≥10 задач) ИЛИ честная рамка «mechanism
  demonstration on compositional depth boundary», не «beats SOTA».
- Обязательный related work: GP-GOMEA, QDSR, AI Feynman 2.0, SRBench,
  Novelty Search (Lehman & Stanley), MAP-Elites (Mouret & Clune).

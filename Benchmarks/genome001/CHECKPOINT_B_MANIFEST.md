## 2. Split и правило словаря

- Словарь D извлекается ТОЛЬКО из train-программ (алгоритм §3), замораживается
  и на test не меняется. Истинные формулы test в построении словаря не участвуют.
- Для REAL train/test: сортировка по каноническому ключу, чётный индекс →
  train, нечётный → test (детерминировано; при n=9: train 5, test 4).
- B и C — baseline'ы целого корпуса: B (DAG) хэш-консится по всем программам
  оси, C (gzip) сжимает конкатенацию всех A-сериализаций (разрешено п.4
  инструкции: «для C разрешить сжатие всего корпуса»). Это осознанно самый
  жёсткий тест для D: слова рождаются в прошлом (train) и должны окупиться
  на будущем (test) против соперников, видящих весь корпус.

## 3. Алгоритм извлечения словаря (заморожен)

1. Для каждой train-программы перечислить все поддеревья; канонический ключ =
   alpha-канонизация (переменные переименовываются по первому появлению в
   x0,x1,…) + сортировка операндов коммутативных операторов (+,×).
2. Кандидаты: узлов ≥ 4; атомы только xN/K1/K2; форма встречается в ≥ 2
   РАЗЛИЧНЫХ train-программах.
3. Сортировка кандидатов: (узлы DESC, distinct_programs DESC, ключ ASC);
   взять первые 32 (cap). Порядок nodes DESC даёт родителям приоритет →
   вложенные слова (T₂→T₁-паттерн) возникают при encode definition против
   уже построенных статей.
4. Имя слова = 'BW'+md5(канонического ключа). Definition = alpha-канонический
   AST формы. Арность = число слотов (контiguity проверяется WordCodec).
5. Строится через WordCodec::buildDictionary (encode каждой definition против
   предыдущих статей) → вложенные {word}-ссылки внутри словаря легальны.

## 4. Представления (п.3-4)

Все размеры в байтах JSON (UTF-8, unescaped slashes) — сопоставимая база.

- **A** — сумма per-program `json_encode(AST)`.
- **B** — глобальный DAG: hash-cons всех узлов всех программ оси (канонический
  ключ узла, коммутативные операнды сортируются); таблица `[op,l,r]`/`[atom]` +
  корневые id; размер = `strlen(json({table, roots}))`. Подвыражения шарятся
  между программами (п.3 инструкции).
- **C** — `gzencode(concat(A_i, "\n"), 9)` всего корпуса. Кодек: встроенный
  deflate PHP (ext-zstd в окружении отсутствует — проверено; gzip = Lempel-Ziv
  семейство,lossless, уровень 9). Версия: PHP 8.2.29.
- **D** — `WordCodec::serializeBundle(dictionary, genomes)` = словарь + все
  геномы (train+test) + метаданные формата. Словарь — train-only (§2-§3).
  Полная стоимость: bundle целиком, словарь не вычитается.

## 5. Метрики (п.5-7)

Для каждой оси × корпуса:
- total bytes (A/B/C/D), dict_bytes (D);
- marginal bytes/program: эмпирическая производная по COUNT-оси (D: прирост
  bundle при добавлении программы при замороженном словаре);
- compression ratio: D/A, D/B, D/C (по total);
- encode wall, decode wall (`WordCodec::decode`, полное развёртывание всех
  программ), execution wall (evalNode всех программ × 10 строк: original и
  decoded), peak RAM фаз (memory_get_peak_usage(true));
- break-even: минимальный N (COUNT-ось), где D_total < X_total для X ∈ {A,B,C};
- semantic errors: структурная/каноническая эквивалентность decode(encode(P))
  и decodeExpanded(encode(P)) + численная эквивалентность на 10 сидированных
  строках + 2 строки с нулевым знаменателем (x0==x1) — счётчик обязан быть 0;
  R-атомные программы — structural-only (численная проверка пропускается
  осознанно, счётчик numeric_skipped).

## 6. Критерии вердиктов (прегистрация, «Основные исходы» owner)

- **H1 lossless heredity**: PASS ⇔ semantic_errors = 0 во всех корпусах/осях.
- **H2 structural compression**: PASS ⇔ D_total < A_total на REGULAR
  (SIZE-ось, test). Отдельно фиксируются D vs B и D vs C (без смешивания).
- **H3 complexity scaling**: PASS ⇔ на REGULAR отношение genome_bytes/ast_bytes
  убывает с ростом развёрнутого размера; на RANDOM фиксируется направление
  (ожидание: убывания нет).
- **H4 no automatic advantage**: фиксируется как есть: D < B? D < C?
  Проигрыш D соперникам = «преимущество хранения не подтверждено» (без спасения).
- **H5 cost**: таблица wall/RAM; вердикт = trade-off задокументирован, ни одна
  метрика не спрятана.
- REGULAR / RANDOM / REAL не усредняются между собой (п.6).

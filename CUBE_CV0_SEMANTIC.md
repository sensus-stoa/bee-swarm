## 0. БАЗОВАЯ ЛИНИЯ: что есть сейчас

### 0.1. Фактическое состояние системы
```
swarm.db: 405 семантических фактов, 6 числовых законов, 1040 grammar_ops
Все 405 фактов: confidence = 1.0, predicate = 'is_a'
Законы: 6 арифметических (sq, max, sqrt, div, mul, add), все CV=0, domain=arithmetic
```

**Качество фактов** (первые 15 из БД):
| Субъект | Объект | Качество |
|---------|--------|----------|
| Авито | десятки | ШУМ |
| пессимизм | данные | УСЛОВНО |
| чего | система | ШУМ (стоп-слово) |
| Мысль | первый | ШУМ |
| ОФЗ | ставка | ОК |
| эксперты | производные | ОК |

**Вердикт: ~30-40% фактов — шум.** Механизм confidence tracking (0.3 → +0.15 → +0.15...) не работает — все факты доехали до 1.0 независимо от качества. Причина: отсутствует отрицательная обратная связь (contradiction → −0.4), факты никогда не опровергаются.

### 0.2. Текущая архитектура семантического слоя
```
Source (Obsidian .md / текст)
  → Forager::scanWithAccumulator()
    → SemanticFactInserter::insert(s,p,o)
      → INSERT confidence=0.3 OR UPDATE +0.15
      → ConceptRegistry::register() → хеш
      → Задача foraged_semantic (генерируется, но НЕ подаётся в Search::find)
  → Hive::doTick()
    → if domain == 'foraged_semantic' → INSERT в KG напрямую (МИНУЯ CV→0)
    → if domain != 'foraged_semantic' → Search::find (только для числовых)
```

**Ключевой разрыв:** домен `foraged_semantic` пропускается мимо `Search::find` (Hive.php:199). Семантические данные НЕ участвуют в CV→0 поиске. Это архитектурное решение, не баг — потому что бинарный target (0/1 — факт есть/нет) ломает CV→0.

## 1. ОСЬ ПОЗНАНИЯ: На каком слое достоверности мы работаем?

### 1.1. Слои достоверности (по Викентьеву)

| Слой | Определение | Что в нашей системе |
|------|-------------|---------------------|
| **Факт** | Воспроизводимое наблюдение, подтверждённое ≥2 независимыми источниками | Единичные записи в KG: «ОФЗ is_a ставка» |
| **Гипотеза** | Утверждение с указанными границами применимости и условиями фальсификации | cross-domain bridges: «sqrt связывает biology↔physics» |
| **Байка** | Правдоподобная история без воспроизводимости | ~30-40% фактов KG (шум) |
| **Закон** | Инвариант с CV→0, проверенный на held-out | 6 арифметических законов |

**Текущее состояние:** 405 утверждений в KG — СМЕСЬ фактов и баек. Система не различает слои. Все имеют confidence=1.0.

### 1.2. Что на самом деле меряет confidence?

**Заявлено:** вероятность истинности факта.
**Реально:** счётчик повторных обнаружений.

```
confidence = min(1.0, 0.3 + n × 0.15)
```

Это **частота цитирования**, не достоверность. Три книги могут процитировать один миф → confidence=1.0.

**Корень проблемы:** confidence в KG — дискретный счётчик, а не непрерывная мера. Нет механизма понижения (contradiction penalty не подключён). Нет независимости источников (три копии одного текста = три «источника»).

### 1.3. Вывод по оси ПОЗНАНИЯ
Система работает на слое **«байки + отдельные факты»**, претендуя на слой «факты». Confidence — мимикрия под достоверность. Для CV→0 нужен честный переход на слой «гипотезы» (falsifiable, bounded) и далее «законы» (CV→0).

## 2. ОСЬ СТРУКТУРЫ: На каком уровне решать?

### 2.1. Три уровня

```
НАДСИСТЕМА: другой тип поиска
  (graph invariants, logical inference, subgraph isomorphism)
  ↑
СИСТЕМА: адаптировать CV→0
  (непрерывный confidence через агрегацию истории)
  ↑
ПОДСИСТЕМА: новый fitness-критерий
  (замена CV→0 для семантики)
```

### 2.2. Анализ уровней

| Уровень | Подход | Реализуемость | Риск |
|---------|--------|:---:|------|
| **Подсистема** | Заменить CV→0 на information gain, mutual information, graph entropy | Высокая | Два критерия → две архитектуры → развал единого принципа |
| **Система** | CV→0 на агрегированной истории фактов (stability laws) | Средняя | Холодный старт: нужно 47+ фактов с разной историей |
| **Надсистема** | Graph invariants (subgraph isomorphism, motif detection, logical inference) | Низкая | Полный отказ от CV→0, потеря единого принципа |

### 2.3. Рекомендация: СИСТЕМНЫЙ УРОВЕНЬ + элементы подсистемы

**Почему не надсистема:** CV→0 — ЕДИНСТВЕННЫЙ критерий системы. Его замена — архитектурный перелом. Bee Swarm строился на принципе «один критерий для всего». Graph invariants — другой тип поиска, другая архитектура. Это не эволюция, это замена.

**Почему не только подсистема:** Два fitness-критерия (CV→0 для чисел, entropy для семантики) — нарушение принципа «один движок». Система становится коллекцией разрозненных модулей.

**Почему системный:** CV→0 на МЕТА-уровне (история фактов) сохраняет единство критерия. Stability law — такой же инвариант как Kepler. `CV(stability_formula, actual_stability) → 0` — это тот же Search::find, но на другом домене.

## 3. ОСЬ ОТНОШЕНИЯ: Зачем СИСТЕМЕ семантика?

### 3.1. Что система ПОЛУЧАЕТ от семантики, чего нет в числах?

| Свойство | Числовой домен | Семантический домен |
|----------|:---:|:---:|
| Обнаружение новых доменов | ✗ | ✓ (понятия организуются в иерархии) |
| Кросс-доменные мосты | Слабые (sqrt в physics↔biology) | Сильные («стресс is_a предиктор» → мост health↔psychology) |
| Порождение grammar atoms | ✗ | ✓ (Bee Language Emergence, критерий 3.8) |
| Falsification через contradiction | Только held-out | Естественный механизм (A is_a B vs A is_not B) |
| Абстракция | Нет (только конкретные формулы) | Да (is_a порождает иерархии) |

### 3.2. ФУНКЦИЯ семантики для системы

Семантика — **источник новых grammar atoms**. Когда система находит, что «стресс» и «сон» связаны через `is_a` и `affects`, она может создать composed atom: `affects(is_a(X, predictor), Y)`. Это не может дать числовой домен — там атомы это +, ×, sqrt. Семантика даёт **открытый словарь операций**.

**Формулировка по Долгову:** Семантика — не цель. Семантика — ТОПЛИВО для расширения grammar. Отношение: семантика → grammar → числовые законы на новых доменах.

### 3.3. Вывод по оси ОТНОШЕНИЯ
Системе семантика нужна для **автономного расширения grammar** (NESTED Level 7). Числа дают closed set операций. Семантика даёт open set. Без семантики grammar застывает на BASE_OPS + изобретённом. С семантикой — каждый новый концепт = потенциальный grammar atom.

## 4. ОБРАТНЫЙ ЦИКЛ (ИКР → шаги)

### 4.1. Идеальный Конечный Результат (ИКР)

> **«Система находит семантические инварианты с той же достоверностью, что и числовые, без изменения CV→0.»**

### 4.2. Шаги от ИКР к реальности

```
ИКР: CV→0 работает на семантике как на числах
  ↑
Шаг 5: Stability law с CV<0.05, held-out подтверждён, 47+ фактов
  ↑
Шаг 4: CV→0 на history domain даёт первую stability law
  ↑
Шаг 3: Для каждого факта собираем history vector
        (source_count, independent_count, age_days, contradiction_count)
  ↑
Шаг 2: Включаем contradiction detection — факты МОГУТ опровергаться
        (нужна отрицательная обратная связь, сейчас её нет)
  ↑
Шаг 1: Исправляем confidence tracking
        (сейчас все 405 фактов = 1.0, вариативности нет)
  ↑
ШАГ 0 (СЕЙЧАС): Все факты confidence=1.0, predicate=is_a, ~35% шума
```

### 4.3. Ключевой барьер: ХОЛОДНЫЙ СТАРТ

Stability law требует минимум 47 фактов с **разной историей** (source_count разный, age_days разный, некоторые опровергнуты). Сейчас: 405 фактов с **одинаковой историей** (все confidence=1, нет опровержений, нет учёта возраста).

**Без вариативности в history нет сигнала для CV→0.**

## 5. ПРОТИВОРЕЧИЕ (ТРИЗ)

### 5.1. Формулировка

```
ТЕХНИЧЕСКОЕ ПРОТИВОРЕЧИЕ:
  CV→0 требует непрерывный target y ∈ ℝ
  Семантика даёт дискретный target y ∈ {0, 1} (факт верен / неверен)

ФИЗИЧЕСКОЕ ПРОТИВОРЕЧИЕ:
  Target должен быть непрерывным (для CV→0) И дискретным (природа знания)
  ── в одном домене, в одно время.
```

### 5.2. ТРИЗ-разрешения

#### A. Separation in TIME: накопить историю → confidence станет непрерывным

```
t₁: факт обнаружен → confidence = 0.3 (дискретный счётчик)
t₂: факт подтверждён → confidence = 0.55
t₃: факт опровергнут → confidence = 0.15
...
tₙ: история факта = временной ряд confidence(t)

Теперь target для CV→0 = не "факт верен?", а "как менялась уверенность?"
```

**Реализуемость: ВЫСОКАЯ.** Не требует новых механизмов. Требует: contradiction detection, учёт времени, хранение истории.

**Недостаток:** Холодный старт. Нужно время чтобы накопить историю.

#### B. Separation in SPACE: разные домены — разные критерии

```
Числовой домен: CV→0 на X→y
Семантический домен: Information Gain / Graph Entropy / MDL на (s,p,o)
```

**Реализуемость: СРЕДНЯЯ.** Два критерия — развал единого принципа.

**Недостаток:** Архитектурная сложность. Система теряет единство.

#### C. Separation in STRUCTURE: CV→0 на мета-уровне, другой критерий на уровне фактов

```
Уровень фактов (KG):    confidence tracking (счётчик)
Уровень мета-фактов:    CV→0 на истории фактов → stability law
Уровень grammar:        CV→0 на числовых доменах (как сейчас)
```

**Реализуемость: ВЫСОКАЯ.** Это фактически протокол §3.5.

**Недостаток:** Два механизма вместо одного. Но они не конфликтуют — работают на разных уровнях абстракции.

### 5.3. Рекомендация

**C + A**: Separation in STRUCTURE как архитектура, Separation in TIME как механизм наполнения history. Мета-уровень (CV→0 на истории) ждёт накопления данных. Уровень фактов (confidence tracking) обеспечивает честный сигнал.

## 6. СВЁРНУТЫЕ РЕШЕНИЯ

### 6.1. Решение №1: Confidence Engine (минимальное)

**Суть:** Исправить confidence tracking чтобы он давал непрерывный сигнал.

**Архитектура:**
```
Новый класс: ConfidenceEngine
  - insert(s,p,o, source_id) → confidence
  - contradict(s,p,o, evidence) → снижает confidence
  - compute(s,p,o): float = f(source_count, independent_count, 
       source_reliability, contradiction_count, age_days)

Формула (начальная, НЕ хардкод — позже заменится stability law):
  confidence = sigmoid(α × independent_count − β × age_days − γ × contradictions)
  
Параметры α,β,γ — константы для холодного старта.
После накопления 47+ фактов с историей → Search::find находит реальные значения.
```

**Требуемые изменения:**
1. `SemanticFactInserter` → `ConfidenceEngine` (рефакторинг)
2. Добавить поле `source_id` в KG (для проверки независимости)
3. Добавить `contradiction_count`, `age_days`, `last_confirmed_at` в KG
4. Механизм contradiction: когда новый факт противоречит существующему → штраф
5. Пересчёт confidence как непрерывной функции вместо дискретного счётчика

**Реализуемость: ВЫСОКАЯ (1-2 дня).** Меняется только семантический слой. Числовой не трогаем.

**Оценка:** ⭐⭐⭐⭐ (4/5)

### 6.2. Решение №2: SemanticSearch — CV→0 на history domain (протокол §3.5)

**Суть:** Применить Search::find к домену «история всех фактов».

**Архитектура:**
```
Новый домен: semantic_history
  X = (source_count, independent_count, age_days, contradiction_count, 
       cv_heldout, predictive_superiority)
  y = stable ∈ {0, 1} (был ли факт опровергнут за 30 дней)
  
Поиск: Search::find(X, y, Grammar{+,−,×,/, sigmoid}, depth=2)
  → stability law: P(stable) = f(X)
  
Новый endpoint: POST /search?domain=semantic_history
  → возвращает stability law с CV, held-out, n_facts
```

**Требуемые изменения:**
1. Миграция KG: добавить поля `source_count`, `independent_count`, `age_days`, `contradiction_count`, `was_refuted`
2. `SemanticHistoryBuilder`: собирает X, y из KG для подачи в Search::find
3. Периодический вызов Search::find на домене `semantic_history`
4. Замена хардкод-констант (α,β,γ) на CV→0-найденные коэффициенты

**Реализуемость: СРЕДНЯЯ (3-5 дней).** Требует миграции данных, накопления истории (холодный старт), интеграции с Search::find.

**Критическая зависимость:** Решение №1 должно работать ПЕРВЫМ. Без честного confidence tracking нет вариативности в history → нет сигнала для CV→0.

**Оценка:** ⭐⭐⭐⭐⭐ (5/5 — целевая архитектура)

### 6.3. Решение №3: Semantic Bridge — семантика как источник grammar atoms

**Суть:** Не применять CV→0 к фактам. Использовать семантику для РАСШИРЕНИЯ grammar, а CV→0 оставить для чисел.

**Архитектура:**
```
KG факт: «стресс is_a предиктор» + «сон is_a восстановление»
  ↓
Pattern Detector: ищет шаблоны в KG
  «X is_a предиктор AND Y is_a восстановление → X affects Y»
  ↓
Grammar Atom Generator:
  Новый составной атом: affects(is_a(X, предиктор), is_a(Y, восстановление))
  ↓
AtomRegistry::add(«affects_predictor_recovery»)
  ↓
Search::find использует новый атом на ЧИСЛОВЫХ данных
  (например: стресс[0-10] × сон[часы] → восстановление[%])
  CV→0 работает как обычно — на числах.
```

**Требуемые изменения:**
1. `PatternDetector`: поиск структурных шаблонов в KG (subgraph mining)
2. `AtomGenerator`: шаблон → candidate grammar atom
3. Интеграция с `AtomRegistry`: атомы из семантики попадают в grammar
4. Валидация: только те атомы которые дают CV→0 на числовых данных выживают

**Реализуемость: СРЕДНЯЯ (5-7 дней).** Требует subgraph mining, который сложен. Но результат — не CV→0 на семантике, а семантика → grammar → CV→0 на числах. Это другой путь.

**Преимущество:** Не требует изменения CV→0. Семантика — источник разнообразия, а не домен для поиска инвариантов.

**Недостаток:** Не даёт семантических законов. Только числовые.

**Оценка:** ⭐⭐⭐ (3/5 — мощно, но не решает прямую задачу)

### 6.4. Решение №4: Coherence Metric — другой fitness для семантики

**Суть:** Признать, что CV→0 не работает на бинарных данных, и ввести параллельный критерий.

**Варианты критериев:**

| Критерий | Формула | Что меряет |
|----------|---------|------------|
| **Graph Entropy** | H = −Σ p(class) log p(class) | Структурированность KG |
| **Modularity** | Q = Σ(e_ii − a_i²) | Качество кластеризации концептов |
| **Coherence** | C = 1 − contradictions/total_facts | Внутренняя согласованность |
| **Compressibility** | MDL(KG) / MDL(random) | Сжимаемость графа |

**Архитектура:**
```
SemanticFitness:
  - computeCoherence(): float  (1 − contradictions/total)
  - computeModularity(): float  (структурированность)
  - computeGraphEntropy(): float  (информационная насыщенность)
  
Цель: максимизировать coherence + modularity, минимизировать entropy
  → максимизировать semantic_fitness
```

**Реализуемость: ВЫСОКАЯ (1-2 дня).** Метрики считаются за O(N).

**Недостаток:** Два критерия — развал единого принципа. Но если CV→0 на семантике честно невозможен — это честное решение.

**Оценка:** ⭐⭐⭐ (3/5 — честно, но архитектурно не чисто)

## 7. ЧЕСТНЫЙ ВЕРДИКТ

### 7.1. CV→0 на семантике возможен?

```
НА УРОВНЕ ФАКТОВ:                 НЕТ (структурно невозможно)
НА МЕТА-УРОВНЕ (stability laws):  ДА (теоретически)
```

### 7.2. Почему на уровне фактов невозможно

**Математическое доказательство:**

```
CV = σ(ratio) / |μ(ratio)|
ratio_i = vec_i / y_i

Для бинарного target y ∈ {0, 1}:
  - Если предиктор выдаёт confidence ∈ [0,1]:
    - Для положительных примеров (y=1): ratio = confidence/1 ∈ [0,1]
    - Для отрицательных примеров (y=0): ratio = confidence/0 → ∞ (или 1e8 с эпсилон)
    
  → CV→∞ для любого нетривиального предиктора.
  
Для константного предиктора (всегда confidence=1):
  - На y=1: ratio = 1/1 = 1
  - На y=0: ratio = 1/0 → ∞
  → CV → ∞
```

**Это не баг. Это свойство математики.** CV требует чтобы target был непрерывным и ненулевым. Бинарный target с нулями делает CV→0 недостижимым.

### 7.3. Что работает на мета-уровне

Stability law (протокол §3.5) обходит проблему:

```
Вместо: CV→0 на (s,p,o) → верен ли факт?
Делаем: CV→0 на истории фактов → стабилен ли факт?

Target: stable ∈ {0, 1} — БИНАРНЫЙ.
НО: stability law ищет f(source_count, independent_count, ...) → P(stable)
    где P(stable) ∈ [0,1] — НЕПРЕРЫВНАЯ вероятность.

Хитрость: Search::find ищет f такую что f(история) ≈ stable.
         stable бинарный, но f(история) непрерывная → 
         CV(f(история) / stable) всё ещё проблематичен из-за stable=0.
```

**Честно:** протокол §3.5 elegant, но математически содержит ту же проблему — target `stable` бинарный. Однако с 47+ фактами CV на бинарном target может быть осмысленным если:
1. Доля positive/negative не экстремальна (не 99%/1%)
2. Используется log-loss вместо CV для оценки

### 7.4. Что делать вместо CV→0 на семантике

#### ВАРИАНТ А: Stability Law через log-loss (честная замена)

```
Вместо: CV(stability_formula, stable) → 0
Делаем: log-loss = −[stable × log(p) + (1−stable) × log(1−p)] → 0

log-loss = 0 ⇔ p = stable для всех примеров
log-loss работает на бинарном target.
```

Это ЗАМЕНА CV→0 для семантического домена. Честная. Математически корректная.

#### ВАРИАНТ Б: Непрерывный confidence как target

```
Вместо: target = stable ∈ {0, 1}
Делаем: target = confidence_history(t) ∈ [0, 1] — временной ряд

Тогда: CV(предсказанный_confidence, реальный_confidence) → 0
       работает, потому что оба непрерывны.
```

Требует хранения истории confidence для каждого факта. Больше данных, но математически чисто.

#### ВАРИАНТ В: Графовые инварианты вместо CV→0

```
Вместо: найти expression с CV→0
Делаем: найти подграфы, которые СЖИМАЮТ KG

Пример: если 50 фактов «X is_a Y» покрываются одним правилом
        «все животные is_a организмы» — это графовый инвариант.
        
Мера: compression_ratio = size(KG) / size(compressed_KG)
      → стремится к максимуму.
```

Это не CV→0. Это другой тип поиска. Но сохраняет принцип «сжатие = обнаружение закона».
